The public plan uses the phase identifier `release`. Evidence initialization, independent advice, implementation acceptance and trace finalization admit it. Required report generation then refuses the accepted trace because its phase projector recognizes only dotted numeric identifiers. The failure message says the trace is absent or belongs to another phase even though the finalized root operation is `phase.release`.

Containment preserves the accepted implementation evidence and parks before the handoff gate or delivery; no identity is invented and no report omission is treated as authorized. A future explicitly scoped correction should reconcile phase identity across admission and every required close consumer, or reject unsupported identity before expensive work. This is a candidate lesson, not permission to edit the schema, policy or machinery. The related input-park recorder also refused this identifier earlier; its duration remains unavailable rather than zero.

Superseding assessment, October 19, 2026: the operator clarified that this task is a bounded fix, not commissioned phase work. The initial diagnosis stopped too late: the repair had been attached to the sole public release phase without a demonstrated matching deliverable or prior accepted phase critique. Its local correction brief did not commission public package/tag/release preparation. The report refusal remains an accurately preserved observation, but it does not establish a report-generator repair as a prerequisite for this bounded task. The earlier proposed machinery remedy is superseded for this incident. Correct only the agent's own task classification, preserve original records, and retain independent review, both unchanged full gates and the delivery guard. This clarification is task-scoped; genuine phase report obligations and general enforcement remain intact. No claim is made that the product defect arose from drift since an earlier checkpoint.
